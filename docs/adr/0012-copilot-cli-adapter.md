# 0012 — GitHub Copilot CLI adapter

- Status: accepted
- Date: 2026-10-14
- Spec: §6.3.2 (adapters), §6.4 (tool grants), §1.4 (one account per provider)
- Builds on: ADR 0004 (neutral grant), ADR 0005 (quota-aware retries)

## Context

The user has a GitHub Copilot plan with a limited monthly allowance of premium requests, and GitHub Copilot CLI (1.0.98) runs headless: `copilot -p <prompt> --output-format json` prints one JSON event per line. The planned Model Router should send simple tasks to Copilot while its allowance lasts, so Navarch needs a `copilot` adapter first.

A probe run on 2026-10-14 (one premium request, `gpt-6-luna` chosen by Copilot's auto mode) showed the event format and how its permissions behave headless:

- With `--allow-tool 'shell(ls)'` the model's first call, `ls && printf 'hi' > hello.txt`, was denied (`tool.execution_complete` with `error.code: "denied"`). The model then ran `ls` alone and wrote the file with `apply_patch`, allowed by `write`.
- The closing `result` event carries `sessionId`, `exitCode` and `usage.premiumRequests`, but no tokens. Token counts per model are written only to `--usage-output-file`.

## Decision

- **Adapter `copilot`** in `packages/adapters/copilot`, registered in `AdapterId` and `buildAdapters`, enabled by default (`adapters.copilot` in the config).
- **Grant translation** (enforcement `exact`): `editFiles` → allow `write`, otherwise deny `write`; each allowed command → `shell(<cmd>)` or `shell(<prefix>:*)`; denied prefixes → `shell(<prefix>:*)`; denied paths → `write(<absolute path>)`; no network → deny `url`. Copilot's path verification already keeps file tools inside the working directory, and `--disallow-temp-dir` removes its default access to the system temp directory. `--allow-all-tools` is never passed.
- **No built-in MCP servers** (`--disable-builtin-mcps`): Copilot's GitHub MCP server would talk to GitHub with the operator's credential, and only the GitHub Integration may do that (architecture rule 5). `--no-ask-user` and `--no-auto-update` keep the run unattended and on a known version.
- **Resume:** a new attempt passes `--session-id <uuid>` generated by the adapter, which is emitted as the resume token before the CLI starts. A retry passes `--resume <id>` with the resume prompt, and falls back to a new session when the old one is gone.
- **Usage:** tokens come from the usage file (a per-attempt temp directory, removed afterwards), recorded at cost 0 like the other plan-based adapters.
- **Quota:** premium requests reset at 00:00 UTC on the 1st of each month. A rate-limited failure whose message mentions premium requests, a monthly limit or AI credits gets `retry_at` at the next reset and emits a `quota` event (`premium_requests_monthly`, exhausted). That reset is more than 12 hours away on most days, so ADR 0005 pauses the run until `navarch run resume`.

## Consequences

- A Copilot plan becomes usable capacity, at one or more premium requests per prompt (the probe used 1 for 4 model calls).
- 🟡 The quota-exhausted message has not been seen in a real run; the adapter relies on the shared rate-limit classifier plus the monthly wording above. The error event name (`session.error`) is also inferred. Both are covered by the fake CLI and should be checked against the first real exhaustion.
- 🔴 The operator's user-level Copilot configuration (`~/.copilot`: custom instructions, installed plugins, MCP config) still applies, unlike Claude Code (`--setting-sources project,local`) and gemini-cli (per-task home). A per-task `COPILOT_HOME` would also need the login, which Copilot keeps there; isolating it is left for later.
- `-p` passes the prompt as one argument, so a prompt is limited to the kernel's per-argument size (128 KiB on Linux). Task prompts are far smaller today.
